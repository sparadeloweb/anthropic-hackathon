# Generating Website Designs for Leads via Stitch

Creates professional website designs in Google Stitch for business leads scraped by `/sales-finding-leads`. Analyzes each lead's data (photos, reviews, hours, type, location) to generate tailored designs.

## Prerequisites

Stitch MCP must be configured. See [SETUP-STITCH.md](SETUP-STITCH.md) for instructions.

Leads data must exist in `./leads/` (generated by `/sales-finding-leads`).

## Workflow

```
Design Generation Progress:
- [ ] Step 1: Select leads to design for
- [ ] Step 2: Analyze lead data and define design direction
- [ ] Step 3: Create Stitch project + design system per lead
- [ ] Step 4: Generate screens
- [ ] Step 5: Review and iterate
```

### Step 1: Select leads and project type

**1a. Select leads:**

Ask the user which leads to process:

1. **Single lead** — user picks one by name from the JSON
2. **Custom selection** — user provides a list of names or indices
3. **All without website** — filter `leads_data.json` where `websiteUri` is empty
4. **All leads** — process every lead in a date folder

Load the JSON from the latest `./leads/YYYY-MM-DD/*/leads_data.json` or let the user specify which search folder.

To read lead data:
```bash
python3 -c "
import json, sys
data = json.load(open(sys.argv[1]))
for i, l in enumerate(data):
    web = 'NO WEB' if not l.get('websiteUri') else 'has web'
    print(f'{i}: {l[\"displayName\"][\"text\"]} | {web} | rating: {l.get(\"rating\",\"-\")}')
" ./leads/YYYY-MM-DD/query-slug/leads_data.json
```

**1b. Project type — ask explicitly:**

| Option | Description |
|---|---|
| **Single Page (Landing)** | One long scrollable page with all sections (hero, services, reviews, contact) as anchored blocks |
| **Multi Page (Website)** | Separate screens per section + a home page with navigation linking to each page |
| **App (Mobile)** | Mobile-first app screens: onboarding, home feed, profile, booking/contact |

**1c. Platform — ask explicitly:**

| Option | Device Type | Notes |
|---|---|---|
| **Web Desktop** | `DESKTOP` | Standard website, generates mobile variant too |
| **Web Mobile-first** | `MOBILE` | Mobile-first, generates desktop variant too |
| **App iOS/Android** | `MOBILE` | Native app screens, no desktop variant |
| **Tablet** | `TABLET` | Tablet-optimized layout |

### Step 2: Analyze lead data and define design direction

For each selected lead, extract and analyze:

- **Business type** (primaryTypeDisplayName) → informs layout style
- **Photos** → analyze visual identity, color palette, style
- **Reviews** → extract key selling points, testimonials
- **Rating + count** → social proof positioning
- **Hours** → schedule section content
- **Address + phone** → contact section content
- **Editorial summary** → if available, use as hero copy basis

Apply design principles from [DESIGN-PRINCIPLES.md](DESIGN-PRINCIPLES.md) to decide:
- Color palette (extract from photos or use business-appropriate defaults)
- Typography pairing
- Layout structure
- Tone of voice for copy

### Step 3: Create Stitch project + design system

For each lead, call Stitch MCP tools in order:

**3a. Create project:**
```
mcp__stitch__create_project({ title: "Lead Name - Website" })
```

**3b. Create design system** based on analysis:
```
mcp__stitch__create_design_system({
  projectId: "PROJECT_ID",
  designSystem: {
    displayName: "Lead Name Brand",
    theme: {
      colorMode: "LIGHT" or "DARK",
      headlineFont: chosen font,
      bodyFont: chosen font,
      roundness: "ROUND_EIGHT",
      customColor: "#extracted-color",
      colorVariant: "TONAL_SPOT" or appropriate variant,
      designMd: "Design instructions based on lead analysis..."
    }
  }
})
```

See [DESIGN-PRINCIPLES.md](DESIGN-PRINCIPLES.md) for font and color guidance by business type.

### Step 4: Generate screens

Generate screens using `generate_screen_from_text` with rich, detailed prompts built from the lead data. Use `GEMINI_3_1_PRO` for best quality.

See [SCREEN-PROMPTS.md](SCREEN-PROMPTS.md) for prompt templates per screen type.

**Choose screens based on the project type selected in Step 1b:**

#### Single Page (Landing)

Generate **1 screen** containing all sections as a long scrollable page:

1. **Landing Page** — includes: hero, services preview, featured testimonial, hours, contact info, footer. All sections linked via anchor navigation at the top.

#### Multi Page (Website)

Generate **5+ screens** with a navigation bar linking between them:

1. **Home** — hero + services preview + testimonial + CTA. Navigation bar with links to: Nosotros, Servicios, Opiniones, Contacto
2. **About (Nosotros)** — business story, values, team/gallery
3. **Services (Servicios)** — detailed services grid
4. **Reviews (Opiniones)** — real reviews with ratings
5. **Contact (Contacto)** — address, phone, hours, map, contact form

Every screen must include the same navigation bar and footer for consistency.

#### App (Mobile)

Generate **4-6 screens** as a native mobile app flow:

1. **Splash / Onboarding** — logo, tagline, "Comenzar" button
2. **Home Feed** — business overview, quick actions, featured info
3. **Services / Menu** — scrollable list or grid of services
4. **Reviews** — review cards with swipe or scroll
5. **Profile / Contact** — business info, hours, map, call button
6. **Booking / Appointment** (if applicable) — form to schedule

Use mobile-native patterns: bottom tab bar, sticky headers, card-based layouts.

---

**For each screen**, call:
```
mcp__stitch__generate_screen_from_text({
  projectId: "PROJECT_ID",
  prompt: "detailed prompt from template...",
  deviceType: DEVICE_TYPE_FROM_STEP_1C,
  modelId: "GEMINI_3_1_PRO"
})
```

**Then generate the responsive variant** (skip if App type):
- If primary is DESKTOP → generate MOBILE variant
- If primary is MOBILE (web) → generate DESKTOP variant

**After all screens are generated**, apply the design system:
```
mcp__stitch__apply_design_system({
  projectId: "PROJECT_ID",
  selectedScreenInstances: [screen instances from get_project],
  assetId: "DESIGN_SYSTEM_ASSET_ID"
})
```

### Step 5: Review and iterate

After generating all screens:
1. List the created projects and screen count
2. Ask the user if they want to review any specific screen
3. Use `get_screen` to retrieve screenshots and present them
4. If the user wants changes, use `edit_screens` to modify
5. If the user wants alternatives, use `generate_variants` with appropriate `creativeRange`

## Processing multiple leads

When processing multiple leads, report progress:
```
Processing lead 3/60: "Estudio Juridico Lopez"
  - Creating project... done
  - Creating design system... done
  - Generating Home screen... done
  - Generating About screen... done
  - Generating Services screen... done

```

Pause between leads to respect API rate limits (2-3 second delay).
